## 1. Tabelas e as 4 integridades

As tabelas do projeto são `contas_usuario`, `contas_registroauditoria`, `contas_falhalogin`, `dicionario_categoria`, `dicionario_sinal`, `trilha_modulo`, `trilha_aula`, `trilha_materialcomplementar`, `trilha_progressoaula`, `questionarios_questao`, `questionarios_alternativa` e `questionarios_tentativa`. As demais (`auth_*`, `django_*`) são do framework.

Exemplo de criação, com as integridades declaradas na própria tabela:

```sql
CREATE TABLE public.trilha_aula (
    id bigint NOT NULL,                       -- entidade (chave primária abaixo)
    titulo character varying(100) NOT NULL,
    descricao character varying(500) NOT NULL,
    posicao integer NOT NULL,
    video character varying(100) NOT NULL,
    legenda character varying(100) NOT NULL,
    texto_apoio character varying(2000) NOT NULL,
    publicada boolean NOT NULL,
    modulo_id bigint NOT NULL,                -- referencial (chave estrangeira abaixo)
    CONSTRAINT aula_posicao_positiva CHECK ((posicao > 0)),
    CONSTRAINT aula_publicada_completa CHECK (((NOT publicada) OR
        ((NOT ((video)::text = ''::text)) AND (NOT ((legenda)::text = ''::text)))))
);
ALTER TABLE ONLY public.trilha_aula ADD CONSTRAINT trilha_aula_pkey PRIMARY KEY (id);
ALTER TABLE ONLY public.trilha_aula ADD CONSTRAINT aula_posicao_unica_no_modulo UNIQUE (modulo_id, posicao);
ALTER TABLE ONLY public.trilha_aula ADD CONSTRAINT trilha_aula_modulo_id_b59be126_fk_trilha_modulo_id
    FOREIGN KEY (modulo_id) REFERENCES public.trilha_modulo(id) DEFERRABLE INITIALLY DEFERRED;
```

### Integridade definida pelo usuário

Regras de negócio que o banco também garante, mesmo que alguém altere os dados por fora da aplicação.

| Constraint | Regra | SQL |
|---|---|---|
| `usuario_aluno_completo` | Quem não é administrador tem o cadastro completo (RF001) | `CHECK (is_staff OR (cpf IS NOT NULL AND data_nascimento IS NOT NULL AND termos_aceitos_em IS NOT NULL AND telefone <> '' AND deficiencia <> '' AND contato_libras <> ''))` |

| `aula_publicada_completa` | Aula publicada tem vídeo e legenda (RF013) | `CHECK ((NOT publicada) OR (video <> '' AND legenda <> ''))` |
| `progresso_conclusao_coerente` | Data de conclusão existe se, e somente se, a aula está concluída | `CHECK ((concluida_em IS NOT NULL AND status = 'CONCLUIDA') OR (status <> 'CONCLUIDA' AND concluida_em IS NULL))` |
| `tentativa_acertos_validos` | Acertos não passam do total de questões | `CHECK ((acertos <= total))` |
| `alternativa_correta_unica` | No máximo uma alternativa correta por questão (RF014) | Índice único parcial (seção 3) |
| `trg_progresso_conclusao` | Aula concluída não volta a outro status (RF007) | Trigger (seção 2) |

## 2. Trigger `trg_progresso_conclusao`

Na tabela `trilha_progressoaula`, antes de cada `INSERT` ou `UPDATE`: grava a data de conclusão quando o aluno conclui a aula, mantém a data original depois disso e impede que uma aula concluída volte a outro status.

```sql
CREATE FUNCTION trilha_progresso_conclusao() RETURNS trigger AS $$
BEGIN
    IF TG_OP = 'UPDATE' AND OLD.status = 'CONCLUIDA' THEN
        IF NEW.status <> 'CONCLUIDA' THEN
            RAISE EXCEPTION 'Uma aula concluída não pode deixar de estar concluída'
                USING ERRCODE = 'check_violation';
        END IF;
        NEW.concluida_em := OLD.concluida_em;
    ELSIF NEW.status = 'CONCLUIDA' AND NEW.concluida_em IS NULL THEN
        NEW.concluida_em := now();
    END IF;
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER trg_progresso_conclusao
    BEFORE INSERT OR UPDATE ON trilha_progressoaula
    FOR EACH ROW EXECUTE FUNCTION trilha_progresso_conclusao();
```

Como a trigger roda antes das verificações de constraint, a regra `progresso_conclusao_coerente` já encontra a data preenchida.

## 3. Campos indexados

**`sinal_termo_trgm`**: índice GIN com a extensão `pg_trgm` no termo normalizado do sinal (sem acentos e em minúsculas). Ele acelera a busca do dicionário por parte da palavra (`LIKE '%texto%'`), que um índice B-tree comum não atende.

```sql
CREATE EXTENSION IF NOT EXISTS pg_trgm WITH SCHEMA public;
CREATE INDEX sinal_termo_trgm ON public.dicionario_sinal USING gin (termo_normalizado public.gin_trgm_ops);
```

**`alternativa_correta_unica`**: índice único parcial. Só as linhas com `correta = true` entram no índice, então cada questão pode ter várias alternativas, mas apenas uma correta.

```sql
CREATE UNIQUE INDEX alternativa_correta_unica
    ON public.questionarios_alternativa USING btree (questao_id) WHERE correta;
```

## 4. Contas e permissões

| Conta | Papel | Permissões |
|---|---|---|
| `plataforma_libras` | Dona das tabelas; roda as migrations | Dona do banco e de todos os objetos |
| `libras_app` | Aplicação | `SELECT`, `INSERT`, `UPDATE` e `DELETE` nas tabelas; `USAGE` nas sequences; não cria nem altera estruturas |
| `libras_relatorio` | Relatórios | Só `SELECT` na view `vw_progresso_modulo` |

Trecho de [`contas.sql`](contas.sql), executado pelo superusuário `postgres`:

```sql
CREATE ROLE libras_app LOGIN PASSWORD 'troque_esta_senha';
CREATE ROLE libras_relatorio LOGIN PASSWORD 'troque_esta_senha';

GRANT CONNECT ON DATABASE plataforma_libras TO libras_app, libras_relatorio;
GRANT USAGE ON SCHEMA public TO libras_app, libras_relatorio;
REVOKE CREATE ON SCHEMA public FROM PUBLIC;

GRANT SELECT, INSERT, UPDATE, DELETE ON ALL TABLES IN SCHEMA public TO libras_app;
GRANT USAGE ON ALL SEQUENCES IN SCHEMA public TO libras_app;
ALTER DEFAULT PRIVILEGES FOR ROLE plataforma_libras IN SCHEMA public
    GRANT SELECT, INSERT, UPDATE, DELETE ON TABLES TO libras_app;
ALTER DEFAULT PRIVILEGES FOR ROLE plataforma_libras IN SCHEMA public
    GRANT USAGE ON SEQUENCES TO libras_app;

GRANT SELECT ON vw_progresso_modulo TO libras_relatorio;
```

O `ALTER DEFAULT PRIVILEGES` estende as permissões de `libras_app` às tabelas que as próximas migrations criarem. A view roda com as permissões da dona, por isso `libras_relatorio` lê os percentuais sem ter acesso a `contas_usuario`. O script [`verificacao.sql`](verificacao.sql) prova as permissões: `libras_relatorio` lê a view e é recusado em `contas_usuario`; `libras_app` lê e grava dados, mas é recusado ao criar ou alterar tabelas.

## 5. View `vw_progresso_modulo`

Uma linha por aluno e por módulo com aulas publicadas: quantas aulas o módulo tem, quantas o aluno concluiu e o percentual arredondado. A própria aplicação lê a view para mostrar a barra de progresso da trilha (RF006).

```sql
CREATE VIEW vw_progresso_modulo AS
SELECT
    u.id AS aluno_id,
    m.id AS modulo_id,
    COUNT(a.id)::integer AS aulas_publicadas,
    (COUNT(p.id) FILTER (WHERE p.status = 'CONCLUIDA'))::integer AS aulas_concluidas,
    ROUND(
        100.0 * COUNT(p.id) FILTER (WHERE p.status = 'CONCLUIDA') / COUNT(a.id)
    )::integer AS percentual
FROM contas_usuario AS u
CROSS JOIN trilha_modulo AS m
JOIN trilha_aula AS a
    ON a.modulo_id = m.id AND a.publicada
LEFT JOIN trilha_progressoaula AS p
    ON p.aula_id = a.id AND p.aluno_id = u.id
WHERE NOT u.is_staff
GROUP BY u.id, m.id;
```

Como só aulas publicadas entram na contagem, publicar ou despublicar uma aula recalcula os percentuais sem apagar as conclusões já registradas.
